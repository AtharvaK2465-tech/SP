# SysWatch OS Concepts

## `/proc`

Linux exposes process and kernel accounting information through the proc filesystem. It is virtual: files are generated by the kernel rather than stored on disk. SysWatch reads these files directly, so a disappearing process is a normal race and must be treated as an expected read failure.

## Process states

`/proc/[pid]/stat` exposes a one-letter state such as `R` (running), `S` (sleeping), `D` (uninterruptible sleep), `T` (stopped/traced), `Z` (zombie), and `I` (idle kernel thread on newer kernels).

## Signals

`kill(pid, SIGTERM)` requests graceful termination. `SIGKILL` terminates immediately and cannot be caught; SysWatch therefore requires an explicit confirmation flag for the force-kill API. `SIGSTOP` suspends a process and `SIGCONT` resumes it.

## Nice values and scheduling

The nice value influences the scheduler's relative priority for ordinary processes. Lower nice values generally mean higher scheduling priority and require appropriate privilege. SysWatch changes it through `setpriority()` rather than shelling out to `renice`.

## CPU percentage from tick deltas

Linux reports CPU accounting in scheduler ticks. For two samples, SysWatch computes:

`CPU% = 100 × (delta_total_ticks - delta_idle_ticks - delta_iowait_ticks) / delta_total_ticks`

Per-process CPU uses the change in `utime + stime` divided by the kernel clock tick frequency (`_SC_CLK_TCK`) over the one-second collection interval.

## Virtual vs resident memory

Virtual memory is the address space a process can reference. Resident set size (RSS) is the amount currently resident in physical RAM. SysWatch reports RSS for process rows because it is a useful approximation of physical memory pressure caused by a process.

## File descriptors

A process accesses files, sockets, pipes, terminals, and other kernel objects through integer file descriptors. `/proc/[pid]/fd` exposes symbolic links for these descriptors, which SysWatch resolves with `readlink()`.

## Memory maps

`/proc/[pid]/maps` describes virtual address ranges, permissions, offsets, and mapped files. These mappings include executable images, shared libraries, anonymous memory, stacks, and heaps.
